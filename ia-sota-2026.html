AI agents: context and the state of the art

1 / 5

It's autocomplete, just a very good one

  • An LLM does one thing: it continues the conversation.
  • It works only from everything read and said so far. That's the context.
  • It has no memory between replies. Each time, it rereads the whole context from the top.
  • Agent = LLM + harness. The LLM decides what to do. The harness does it: reads files, searches, calls APIs. The results go back into the context.

If it's not in the context, the model doesn't know it.

Speaker notes

The simplest way to think about a language model is as a very good autocomplete. You give it a conversation, and it writes the most likely continuation. It does this based only on what is in front of it: everything that has been read and said so far. We call that the context.

The model keeps nothing between replies. Every time it answers, it reads the whole context again from the beginning and writes the next part. That is why a new chat starts from zero: the earlier messages are no longer in the context. When an agent seems to "remember" something from last week, it saved a note earlier and loaded it back into the context.

An agent is a language model inside a harness, a program like Claude Code or Codex. The model only writes text, but that text can be a request: read this file, search for this, call this API. The harness carries out the request and adds the result to the context. The model then continues from there. So the rule holds for agents too: if it's not in the context, the model doesn't know it.

2 / 5

The context holds more than you think

  • Your messages and its answers.
  • Instructions the agent got before you typed a word.
  • Every file, website, and API response it has opened, including the ones it didn't need.
  • It grows with every step and never shrinks unless something cuts it.
  • Bigger context means higher cost, slower replies, and dumber answers.

Many models give the best cost and quality at only 15–20% of their maximum window.

When the context fills up, the agent summarizes or drops older parts. The detail you care about may be gone.

Speaker notes

When you use an agent, you see your own messages and its answers. That is only part of what it reads. Before you type anything, the agent has already received instructions and descriptions of the tools it can use. Then, while it works, every file it opens, every web page and every API response goes into the context too, whether it turns out to be useful or not.

The context only grows, step after step. That has a price. Every reply re-reads the whole thing, so a bigger context costs more and takes longer. It also makes answers worse: the important details get lost among everything else.

Models advertise very large windows, up to a million tokens, but that is the maximum, not the best working size. For top models like Opus and Sol, the best balance of cost and quality is likely around 150 to 200 thousand tokens, about 15 to 20% of the window. The exact point depends on the task, and studies do not agree on it, but the direction is clear.

When the window does fill up, the agent summarizes or drops older parts of the conversation to make room. That keeps it running, but summaries lose detail, and the detail you needed may be one of them.

3 / 5

Practical implications

  • One agent, one job. A focused agent beats one that knows everything.
  • Organize information so agents can find the right part fast: clear structure, clear names, the relevant section rather than the whole file.
  • Every output becomes another agent's input. Low-quality output adds noise to every context that follows.

An agent is only as good as its context, and that includes what the previous agent wrote.

Speaker notes

If the context decides the quality of the answer, the practical goal is simple: give each agent the right information, not as much information as possible.

The first way to do that is focus. An agent with one clear job needs less information, so its context stays small and relevant. An agent asked to do everything has to carry everything.

The second is organization. When documents have clear structure and clear names, an agent can find the right section, not just the right file. It reads what it needs and leaves the rest out of its context.

The third is easy to overlook. Whatever an agent writes, whether a plan, a report or a review, becomes the input of the next agent. Clear, precise output keeps the next context clean. Long or vague output adds noise to every step that follows. So an agent is only as good as its context, and that includes what the previous agent wrote.

4 / 5

Where AI tools stand today

Each step up: fewer decisions, but bigger ones.

Speaker notes

This picture shows where AI tools stand today, as four steps. It helps place any product or vendor. For example, a vendor that builds a prompt from its own documents and starts an agent is on step two. A vendor that offers an automatic loop for reviewing code is on step three.

On the first step, you work with an agent interactively. You ask, read the answer, correct it and ask again, steering every turn. This is often called vibe coding.

On the second step, the work is prepared in advance. Skills, workflows or custom agent definitions describe the task, the instructions and the tools. The agent then completes the task in one go, without anyone steering it.

On the third step, an agent repeats a task until it passes a check, such as tests or a code review. This differs from an ordinary scheduled script: the agent judges the result each time and decides what to fix.

The fourth step is the software factory. Specialised agents break a goal into tasks, prepare them and implement them in parallel. Defined verification and integration steps let this run for hours or days. Real examples exist: Factory's Missions split work into parallel tracks, and Vercel runs a factory for its AI SDK in which nothing is merged without a human maintainer's approval. Both are internal or new, and neither yet starts from requirements or keeps documentation current. This step is still early, and it is the subject of the next part of this talk.

With each step up, people make fewer decisions, but bigger ones. On the first step you decide at every turn. Higher up, you decide how the work is set up, what the goals are, and what gets approved.

5 / 5

What is the secret sauce?

Most skills and workflows are now written by agents. AI is already building the next software factories.

  • They age in months, not years. Code-review skills were among the most-starred on GitHub. Claude Code now has one built in. Ponytail, one of the most-starred skills, has to prove itself again with every model release.
  • A factory made of skills and workflows ages the same way.
  • What lasts: well-structured knowledge (requirements, specs, decisions) that the next agents can reuse knowing what goes into the context, how the work is checked, and where people decide

There is no sauce. Only the cook.

Speaker notes

A year ago, a good skill or workflow was a real advantage. Today, agents write most of them, and they go out of date in months.

Code review is a good example. In 2025, community skills that taught Claude Code how to review code were among the most popular on GitHub. One of them, awesome-skills/code-review-skill, has over 2,000 stars. Anthropic now ships its own code-review plugin with Claude Code. A skill that people collected and maintained became a built-in command.

Even skills that survive have to be checked again. Ponytail makes the agent write less code by reusing what already exists, and it has well over 100,000 GitHub stars. With each new model, people ask whether it is still needed. Reviewers expected newer models to make it pointless.

A software factory built as a set of skills and workflows will go the same way. The parts will be replaced. Two things last. The first is the knowledge the work produces: requirements, specifications, decisions and the reasons behind them. If it is well structured, any new agent, model or workflow can pick it up and continue. If it is buried in chat logs or long reports, it has to be rebuilt each time. The second is the judgment behind the parts: what each agent needs in its context, how its work is checked, and which decisions stay with people. Together they build a factory, and they rebuild it when the parts change.

Also see: Anthropic code-review plugin; Ponytail.
